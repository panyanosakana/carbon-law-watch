# 双碳法规信息自动收集系统

按「专业信息收集助手」规范实现：**仅检索当月**发布、**限定双碳领域**、**3-5 条要点原文摘抄**、**官方原文链接**，输出**网页 + Excel**，由 GitHub Actions 每日自动更新（零积分、零 API 费用）。

## 一、当前实采结果（2026 年 11 月）

| 指标 | 数值 |
|---|---|
| 监测信息源 | 37 个（部委 13 + 地方工信/经信 24） |
| 采集成功 | 36 个（上海市经信委域名在当前网络不可达，已标注） |
| 当月入库 | 示例批次 5 条（随日期实时变化） |
| 近期参考 | 10 条（当月不足时按规则 3b 提供） |

示例条目：《关于印发〈"十五五"新型储能实施方案〉的通知》（发改能源〔2026〕1565号）、《市工业和信息化局关于做好天津市 2027 年电力市场化交易工作的通知》（津工信电力〔2026〕19号）、《工业和信息化部等四部门关于公布工业产品碳足迹核算规则团体标准推荐清单（第四批）的通告》（工信部联节函〔2026〕384号）。

## 二、如何满足你的规则

| 你的要求 | 实现方式 |
|---|---|
| 0）仅检索当月 | `collect.month_only: true`，按发布日期硬过滤；日期取自列表页与正文页双重校验 |
| 1a）指定网址 | `config.yaml` 的 `sources`，逐个可开关 |
| 1b）重点监控渠道 | 发改委/工信部/生态环境部/财政部/能源局/认监委/中国政府网/司法部/市场监管总局/人大网 |
| 1c）领域聚焦 | 26 个核心词（碳达峰、碳中和、碳足迹、CCER、绿电绿证、循环经济、节能、储能等）+ 6 个辅助词 |
| 2a）法规名称 | 标题 + `publisher`（发文机关）+ `doc_no`（文号），文号只采当年且排除引用他文 |
| 2b）3-5 条要点 | 从正文按「目标/任务/范围/奖惩/比例/时间节点」权重抽取**原句**，不改写、不拼凑 |
| 2c）官方链接 | 均指向发文具体页面（gov.cn / 部委 / 地方主管部门域名） |
| 3b）无结果时 | 页面与 Excel 均提供「近期参考」区块，并明确标注发布时间早于本月 |

> 说明：若原文正文以 PDF/OFD 附件形式发布（如发改委部分通知），网页无可摘抄正文，系统会明确标注「正文见附件」，**不生成臆测要点**。

## 三、目录结构

```
carbon-law-watch/
├── config.yaml                    # 信息源、关键词、排除词（唯一需要改的文件）
├── collector/
│   ├── engine.py                  # 采集引擎：抓取→解析→筛选→补全→去重
│   ├── export_excel.py            # Excel 导出（法规清单 + 采集概览）
│   └── requirements.txt
├── docs/index.html                 # 网站：当月法规 / 近期参考 / 信息源状态
├── data/regulations.json          # 网站数据
├── output/双碳法规汇总-YYYY-MM.xlsx  # Excel 交付件（每月一个文件）
└── .github/workflows/update.yml   # 每日 08:00（北京时间）自动运行
```

## 四、本地运行

```bash
pip install -r collector/requirements.txt
python -m playwright install chromium     # 首次需要（用于 JS 渲染站点）
python collector/engine.py                # 生成 data/*.json 与 output/*.xlsx
cd docs && python3 -m http.server 8000     # 浏览 http://localhost:8000
```

## 五、部署到 GitHub（免费、无需积分）

1. 新建仓库，推送到根目录
2. **Settings → Pages**：Source 选 `Deploy from a branch`，分支 `main`，目录选 **`/docs`**
3. **Actions → carbon-law-update → Run workflow** 手动跑一次验证
4. 之后每天 08:00 自动采集、提交，网页与 Excel 同步更新；Excel 也会作为构建产物（Artifact）保留 30 天

## 六、技术要点（为什么这样设计）

1. **不写死 CSS 选择器**：采用「列表页 + 通用条目识别」，部委网站改版后多数仍可工作。
2. **栏目自动发现**：地方站点首页信息少，脚本自动在导航中寻找「政策文件/通知公告/政务公开」栏目，候选量从几十提升到上百。
3. **双通道抓取**：`html`（requests，快）+ `browser`（Playwright 渲染，应对工信部、市场监管总局、中国政府网等 JS 站点），并拦截图片字体资源提速。
4. **噪声治理**：剔除新闻稿/活动报道（启动、举办、座谈等）、收件人抬头、附件文件名、半句残片、与标题高度重复的句子。
5. **文号校验**：只接受「文本开头 + 当年年份 + 非引用语境」的文号，避免把请示编号当发文文号。
6. **诚实兜底**：抓取失败、无正文、当月无结果，均在页面与 Excel 中如实说明，不编造。

## 七、已知限制

| 站点 | 情况 | 处理 |
|---|---|---|
| 上海市经信委 | 域名在当前网络不可达 | `enabled: false`，境内网络可开启 |
| 市场监管总局 | 站点极慢，需浏览器渲染 | 已用 browser 模式，偶发超时则跳过并标注 |
| 发改委部分通知 | 正文仅 PDF 附件 | 标注「正文见附件」，不生成要点 |
| 地方站点栏目 | 各省栏目路径不一 | 靠自动发现，若失效可在 `urls` 手动补充 |
